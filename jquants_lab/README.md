# jquants_lab — J-Quants 読み取り専用接続の実験準備

## 目的

J-Quants Free（12週間遅延の日足・財務データ）を使った日本株の学習実験
パイロットに先立ち、**実データに触れずに**接続部分だけを独立して準備する
ためのパッケージです。本番アプリ（`app.py` や既存モジュール）からは
import されません。既存アプリの動作には影響しません。

現段階の位置づけ:

- 準備のみ。実API接続・実データ取得は行っていません。
- テストはすべて合成データ（`synthetic.py`）とフェイク transport で実行します。
- マージ・本番反映には別途承認が必要です（このパッケージは Draft PR まで）。

背景・利用条件の確認記録は Notion「情報源の新規開拓再開と調査方針の更新
（2026-11-20）」ページの 2026-11-26 各節（J-Quants の ML 利用許可、
パイロット設計、Muse 向け作業指示）を参照してください。J-Quants Free は
個人の投資分析・バックテスト・機械学習の学習と検証が公式 FAQ で許可され
ていますが、データは12週間遅延であり、リアルタイム売買判断用では
ありません。

## セットアップ（将来の実接続時）

APIキーは**環境変数からのみ**読み込みます。ソースコード・ログ・チャット・
Notion・GitHub にキーを貼らないでください。キー発行はユーザー本人が
J-Quants 公式サイトで行います（代行しません）。

```bash
export JQUANTS_API_KEY="<自分のAPIキー>"
# 任意: ベースURLを変える場合のみ
export JQUANTS_BASE_URL="https://api.jquants.com"
```

- 環境変数が未設定・空の場合、クライアントは `MissingApiKeyError` で即座に
  停止し、ネットワーク呼び出しを一切行いません（fail closed）。
- キーは例外メッセージ・リクエストログにも含めません。リクエストログに
  残るのはパス・応答コード・件数だけです。

## API 形状メモ（J-Quants V2、公式仕様とパイロット設計に基づく）

- 認証: リクエストヘッダー `x-api-key`。
- エンドポイント:
  - `GET /v2/equities/bars/daily` — 日足。`date` 指定で当日の全銘柄分。
  - `GET /v2/equities/master` — 銘柄一覧（過去日付指定で当時の上場銘柄）。
  - `GET /v2/fins/summary` — 財務サマリー。開示日基準で扱う。
- ページネーション: レスポンスに `pagination_key` があれば、それを次回
  リクエストに付けて最後までたどる。ページサイズは固定・保証されない。
  本クライアントは、キーの繰り返し（ループ）を検出して停止し、ページ数の
  上限も持つ。
- レスポンスのデータ配列キーはエンドポイントごとに異なる可能性があり、
  明示指定がなければ本文中の唯一のリスト型フィールドを自動検出する。
  **初回の実接続テスト（Pilot 1）で実物を確認すること。**
- Free プラン: 5 リクエスト/分（アカウント単位。キーを増やしても増えない）。
  429 のときは即時再試行せず、最低1分待つ。本クライアントは
  `Retry-After` ヘッダーを優先し、無ければ既定60秒待機。再試行は上限
  （既定3回）までで、上限を超えたら `RateLimitError` で停止する
  （無限リトライはしない）。
- 日足には生系列（Open/High/Low/Close）と調整済み系列
  （AdjustmentOpen 等）があり、区別して保存・検証する前提。

## モジュール構成

| ファイル | 内容 |
| --- | --- |
| `client.py` | 読み取り専用クライアント。環境変数キー、ページング全件取得、重複排除、429 待機・再開（上限つき）、取得ログ（認証情報なし） |
| `quality.py` | データ品質検証。スキーマ（必須項目・NULL）、重複、日付の連続性・順序、OHLC 整合性、調整済み/生系列の有無。財務は開示日の欠落を point-in-time 観点で検査 |
| `evaluation.py` | 時系列評価の準備。時系列順の学習/検証/最終テスト分割（embargo 付き）、point-in-time assert、前方リターン（翌営業日始値エントリー前提）、分類指標、固定モデル vs 候補モデルの比較インターフェース。評価の実行自体は別工程 |
| `synthetic.py` | 合成データ生成器（実データではない）。テスト専用 |

## テストの実行方法

リポジトリ直下で:

```bash
python -m pytest tests/test_jquants_client.py tests/test_jquants_quality.py tests/test_jquants_evaluation.py -q
```

追加の依存はありません（標準ライブラリのみ）。ネットワークアクセスも
行いません。CI でも `tests/` 配下として既存テストと一緒に実行されます。

## 安全上の決まり

- 読み取り専用。書き込み・注文系の機能は持たない。ブローカー接続なし。
- 実データの取得・保存は、ユーザーが Free プラン登録・キー発行・安全な
  設定を完了した後、別途承認を得てから行う。
- 取得データはユーザー本人のみが使う個人用ローカル保存を前提とする。
